> ⚠️ **这是 `0.4.0`，按 SemVer 属于尚未到 1.0 的早期版本。**

## 功能

- **独立置顶浮窗**：不是画在 DSH 页面里的浮层，而是一个**独立的原生进程**（WinForms + WebView2），
  因此能真正压在其他应用之上，也能在 DSH 主窗口最小化甚至隐藏时继续存在。
- **无边框 + 圆角 + 拖角缩放**，标题栏整条可拖动。
- **五颗标题栏按钮**：`＋` 新对话 / `◉` 置顶（图标反映状态）/ `⌫` 清理缓存（点击先闪红）/
  `—` 最小化 / `✕` 关闭。图标全部 GDI+ 自绘，不用字体符号。
- **继承当前会话上下文**：窗口里的对话与 DSH 内置侧边栏是**同一个引擎、同一批 side thread**，
  只是多了一扇窗。
- **多对话管理**：切换、重命名（行内编辑）、删除单条记录，窗口索引记 20 条。
- **即用即焚**：打开后关闭窗口即删除本次对话记录（含落盘文件）。
- **折叠思考过程、渲染代码块、回到底部按钮、中文输入法焦点处理**。
- **四态外观**：浅色 / 深色 / 跟随 DSH / 跟随 Windows。改完**立即生效**，
  原生标题栏与页面同色。
- **完整设置页**（设置 → 悬浮窗）：外观 / 窗口 / 行为 / 缓存与日志四张卡片。
- **缓存与日志清理**：标题栏 `⌫` 或设置页里的「清理」，两个入口做同一件事。
  清不到的部分在**关窗后**与**下次启动时**各补清一次。日志超 18 MB 自动轮转，三份约 54 MB 封顶。

## 安装

见 [README 的「安装」一节](./README.md#安装)。

要点：

- **仅支持 Windows 10 / 11**，且需要 **DSH Desktop**（Web 版不能完整工作）。
- `.exe` 与 WebView2 DLL 已入库，**不需要** .NET SDK 或 WebView2 SDK。
- 装完**必须重启 DSH Desktop** 一次（宿主半边不热重载）。

> 本项目尚未发布到 npm，请按 README 里的「从源码安装」方式安装。

## ⚠️ 三条要知道的事

1. **仅 Windows。** 窗口是 WinForms + WebView2 程序，macOS / Linux 上没有实现。
2. **`window/webview-data/` 里存着你的 DSH 认证 cookie。** 它已被 `.gitignore` 排除——
   **提交任何东西之前请确认它不在暂存区**；也**不要整个删掉它**（会丢登录态与对话关联）。
3. **`window/window-log.txt` 会记录带 token 的认证 URL 与渲染器能力头值。**
   上报问题前请先删掉这些值。详见 README 的「风险提示」。

## 已知限制

- 仅 Windows；DSH Web 版不能完整工作。
- 宿主半边**不热重载**，改 `host.js` 必须重启 DSH Desktop。
- 同一个插件**只有一个浮窗进程**，重复点「浮窗」不会开第二个窗口。
- 没有机器可读的 DSH 版本约束（DSH 插件清单里不存在这样的字段，非本项目疏漏）。
- **无自动化测试。**
- `dsh.client.inject` 依赖 `@deepseek-ai/dsh-client-ui-conversation`，
  该包版本变化可能影响「浮窗」按钮的挂载。

## 二、git tag 方案

### 标签格式

```
v<major>.<minor>.<patch>
```

即 **带 `v` 前缀**的 SemVer。理由：

- 与 DSH 生态既有插件的 Release 习惯一致，社区工具链普遍按 `v*` 匹配；
- 与 `package.json` 的 `version`（**不带** `v`，值为 `0.4.0`）区分开，
  一眼能看出谁是 npm 版本、谁是 git 标签；
- GitHub Release 的自动 tag 建议也默认 `v` 前缀。

### 本版本的标签

| 项 | 值 |
|---|---|
| tag 名 | `v0.4.0` |
| tag 类型 | **annotated**（轻量标签不带附注，不利于归档） |
| 指向 | `main` 上 `plugin/package.json` 版本为 `0.4.0` 的那个提交 |
| 标题 | `dsh-float-chat v0.4.0` |

### 创建命令

```bash
# 确认工作区干净、且版本号已对齐
git status
git log --oneline -1
grep '"version"' plugin/package.json

# 创建带附注的标签
git tag -a v0.4.0 -m "dsh-float-chat v0.4.0

首次公开开源（早期版本，非 1.0）：把 DSH 侧边对话弹成独立置顶浮窗，
可覆盖在任何应用之上，自带四态外观、几何记忆、即用即焚与缓存清理。

依赖 DSH Desktop 的渲染器能力头；仅支持 Windows。"

# 推送标签
git push origin v0.4.0
```

### 后续版本的递增规则（0.x 阶段）

**0.x 阶段的 SemVer 语义与 1.0 之后不同**，这里如实说明并按此执行：

| 变更类型 | 递增位 | 示例 |
|---|---|---|
| 修 bug、改文档、改文案 | patch | `v0.4.0` → `v0.4.1` |
| 新增功能、调整行为、调整接口 | minor | `v0.4.0` → `v0.5.0` |
| **改用不兼容的方式调整接口或配置语义** | minor（0.x 惯例） | `v0.4.0` → `v0.5.0` |

> 在 `1.0.0` 之前，**minor 位承担了 major 的职责**：任何不兼容的改动都进 minor。
> 等接口稳定、愿意对外承诺兼容性之后，再切到正常的 `1.0.0` 语义。

**特别约定**：**扩大清理范围**的改动，无论版本号怎么涨，都必须在 CHANGELOG 的 `Security` 段
与 README 的清理范围表格里同步说明。

### pre-release 约定（如需）

```
v0.5.0-rc.1
v0.5.0-alpha.1
```

发布预览版时使用 SemVer 的 prerelease 段，且**必须**在 GitHub Release 上勾选 *Set as a pre-release*。

### ⚠️ 关于 `dsh.compatibility`：该字段不存在，此项作废

早先的清单把「缺少 `dsh.compatibility`」列为缺口 —— **这个判断是错的**，
它是**臆造**出来的字段。已实地核对 DSH Desktop 2.0.15 的实现：

- 穷举 `resources/app/lib/*.js` 中所有对 `dsh.*` 的读取，**只有两处**：
  `bundleManifest.dsh?.bundle`（`lib/profile-B8k_aHEa.js:701`）与 `dsh?.profile`（同文件 `:680`）。
  插件 `package.json` 里没有任何其他被消费的 `dsh.*` 字段。
- `compatibility` 确实存在，但它在**另一个地方**：`dsh-community-market` 包的
  **目录条目 schema**（`docs/schemas/catalog-provider-page.schema.json`），
  形状是 `{ "apiVersion": string, "hosts": string[] }`，描述的是**市场目录里一条记录**，
  与插件自身的 `package.json` 无关，插件作者也无从填写。
- 因此：**不加该字段**。README「已知限制」与 CONTRIBUTING 里对应的表述已一并改正。

### 可选但推荐

若**不发布 npm**，可以（非必需）把预构建产物挂到 GitHub Release 并在条目里加 `tarball:` 字段——
市场会优先展示 tarball。本插件是「无构建步骤的 JS + 已入库的 `.exe`」，
源码安装即可用，**此步非必需**。

### 关于「和 DSH 官方挂钩」

**没有官方对接渠道。** 官方 `deepseek-ai/deepseek-harness` 仓库的
`docs/user/develop/basic/publish.md` 只讲了「怎么把插件打包成 bundle 并用 `dsh plugin add` 安装」，
**没有**任何「提交插件到官方市场」的流程——因为官方不运营插件市场。
社区生态完全建立在三件事上：

1. 仓库声明 `dsh.bundle`（**这是唯一的机器可读契约**）
2. 仓库打上 `dsh-plugin` topic（GitHub 层的发现机制）
3. 向 awesome-dsh-plugin 提 PR 收录（第三方目录）

`dshmarket`、`dsh-find-plugin` 这类插件市场客户端，正是靠读这些数据来展示插件的。
